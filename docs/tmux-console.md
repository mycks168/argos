# 常駐スロットの端末表示

## 表示と音声

通常・SP・Gridで同じ端末ページを埋め込む。CLI方式のスロットは従来表示を維持する。
tmuxの画面を疑似的にテキスト化せず、実PTYにattachしたクライアントの出力をxterm.jsへ渡す。
表示領域の実寸に合わせてPTYとtmuxの列・行を変更する。再接続時は同じCLIを再表示する。

音声・テキスト欄からの入力は既存の会話APIとRunnerを通す。
端末内で直接入力したターンは、入力を再送せずStop本文だけを既存の履歴・TTS処理へ接続する。
途中のツール出力や端末の装飾は読み上げない。Gridのフォーカス・共通ミュートは既存処理を使う。
端末内のSpaceは通常の文字入力で、音声開始には明示的な音声ボタンかPTTキーを使う。
端末の「読み上げ停止」またはEscapeでブラウザ音声を停止できる。
EscapeはCLIへも渡すため、CLI側の操作取消も起こりうる。音声だけを止める場合はボタンを使う。
通常・SP・Gridは同じスロット別音声キューを使い、非選択スロットの音声は保留する。
再生途中に切り替えた文は、元スロットへ戻った際にその文の先頭から再生する。
PTT・音声入力開始・ミュートによる取消では、保留音声と遅着する同世代の音声も破棄する。
「回答を再生中」は音声の取得待ちでなく、ブラウザの再生開始後に表示する。
通常・SPでは録音停止とデータ確定後、送信前に録音中を解除して処理中へ進む。
録音中の表示を維持するガードが回答処理や次の録音を妨げないようにする。
端末のフォーカス通知は手動入力として数えず、音声入力を妨げない。

音声入力と端末の書きかけを混ぜないため、ターンのファイルロックと手動入力マーカーで競合を拒否する。
書きかけを破棄する「入力取消」はCtrl+Uを送り、音声入力へ戻れる状態にする。
これは実行中のモデル処理を中止する機能ではない。
Claude初期化前の文字欠落を防ぐため、最初の文字入力はSessionStartまで待つ。
ログインや初期信頼確認は起動前に済ませる。起動確認できない場合は本文を送らずエラー表示する。

## API

既存の会話APIは維持し、端末のバイト列搬送だけ別の責務として追加する。
全要求で既存のBearer認証が必要。閲覧Cookieだけでは端末を操作できない。

| 経路 | 用途 |
|---|---|
| GET `/api/terminal/slots` | 各スロットに`execution_mode`を追加。旧クライアントは追加項目を無視できる |
| POST `/api/terminal/console` | JSONの`action`でopen/input/resize/closeを指定 |
| GET `/api/terminal/console?connection_id=…&offset=…` | 最長15秒の長時間ポーリングで出力取得 |
| POST `/api/terminal/turn?input_mode=observe` | 端末に送信済みのターンを観測。通常入力へのフォールバックは禁止 |

openは`name`・`provider`・`columns`・`rows`を受け、`connection_id`を返す。
inputは`connection_id`とbase64の`data`、resizeは接続IDと寸法、closeは接続IDを受ける。
readは`offset`・base64の`data`・`is_closed`を返す。UTF-8途中でもバイト列を変換しない。
追加項目`has_pending_turn`は未回収の端末ターンを示す。省略時はfalseとして扱い、旧版との互換性を保つ。
ブラウザは送信通知を失っても、この項目から既存observe経路で回答を回収する。同じスロットの回収は同時実行しない。
完了後に次の入力が来ても、未回収の完了記録は別ファイルへ保持する。Enter時点の台帳位置を基準にし、入力途中に届いた前の回答を混ぜない。
antigravityで失敗通知の後に正常完了が届いた場合、pendingに保存した世代と台帳位置から
確定本文を照合し、既存observe経路で回収する。回収に成功してからpendingを削除し、入力は再送しない。
正常完了が未到着・本文が空・別世代の場合は、未確定記録を保持する。
読込位置を保持して再取得でき、出力を取りこぼした場合はエラーにして再接続する。

長命トークンはURLに含めず、同一originの親画面からiframeへ検証付きpostMessageで渡す。
iframe側もoriginと送信元を確認する。接続先の認証値はサーバー内だけで保持する。
iframeは操作受付の準備完了を親へ通知し、親は送信元を検証して設定を再送する。
初期化失敗は状態欄へ表示し、音声入力・再接続ボタンの受付は維持する。
「再接続」は設定を再要求して端末初期化も再試行する。ブラウザの戻る・進むで
ページが復元された場合も接続処理を再開し、接続ループの二重起動を防ぐ。
Originヘッダー付きの端末要求はHostとの一致を確認する。
ARGOSの本人確認ロック中も直接端末を操作できない。

## 接続と制限

- 1ブラウザ接続につき1つのattach。閉じるのはattachだけで、CLIは残す。
- 出力バッファ1MiB、1回の出力最大32KiB、キー入力最大64KiB、接続数最大16。
- 90秒間読込がない接続は回収する。リモート中継も同じ期限で登録簿から回収する。
- 寸法は2〜1000列/行。リサイズ要求は80ミリ秒でまとめる。
- スロット名から任意のシェルやtmux名を作らず、定義済みの所有セッションだけを操作する。
- tmuxのprefix/prefix2は当該セッションだけ無効化し、ブラウザから他セッションへ切り替えない。
- ブラウザ切断後の入力は自動再送しない。処理が未確定なら勝手に新しい会話を始めない。

端末接続状態とモデルの処理状態は別。接続済みはCLIの応答完了を意味しない。
本人確認ロック時や起動失敗時はエラーを表示する。
同時に複数タブから書く運用は推奨しない。回答待ち・音声との同時送信は拒否するが、複数タブの書きかけを別のドラフトとして管理する機能はない。

リモートはSSHホストへ直接起動せず、更新済みの接続先ARGOSの同じ認証付きAPIを中継する。
能力照会は60秒キャッシュし、旧版・接続失敗時は従来方式へ戻す。
別実機の認証・ネットワーク条件での試験は未実施。ローカルの実HTTP往復では全端末操作を確認した。

## 配布物

xterm.js 5.5.0とaddon-fit 0.10.0を`static/vendor/`へ同梱する。いずれもMITライセンス。
ライセンス本文も同梱し、実行時のCDN接続は不要。第三者配布物は自作コードの品質・重複検査から除外する。

## 残る対象

Codex・agyの対話型アダプターを追加した。設定・起動確認・フックの違いは[3CLIの試験手順](tmux-agents-trial.md)を参照。
OS再起動後のCLI再開、systemdのtmuxライフサイクル統合、未確定ターンの自動復旧は対象外。
ブラウザ再接続と、終了したCLIの復元は区別する。実マイク・実スピーカーでの聴取確認も自動試験とは分ける。
