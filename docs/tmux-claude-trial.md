# Claude 1スロットの常駐会話試験

Claude 1スロットから始めた試作。通常・SP・Gridの会話領域に、tmuxへ接続した実ターミナルを表示する。既存のCLI方式は残す。続いてCodex・agyも追加したので、[3CLIの試験手順](tmux-agents-trial.md)も参照。リモートARGOSへの端末搬送は実装し、HTTP往復を試験済みだが、別実機での結合試験は未実施。

## ARGOSの画面・音声で試す

運用設定の末尾に「クロード常駐テスト」を追加した。既存5スロットと既定の「デフォルト」は変更しない。試験スロットではツールとMCPを無効にし、PTTの巡回対象には含めない。画面で明示的に選択してからPTT・スペース入力を使う。

設定反映にはARGOSとAgent Runnerの再起動が必要。この会話自体がRunner配下なので、返信と実行中ジョブの完了を待つ外部の一回限りの適用処理で再起動する。設定のバックアップは所有者専用の `~/.config/argos/backups/config.before-claude-tmux-trial-20261015.yaml` に保存した。

再接続後は通常・SP・Gridの画面を再読み込みし、「クロード常駐テスト」を選ぶ。会話領域がClaudeのターミナルへ変わる。端末へ直接入力してEnterで送信すると、確定回答を既存の読み上げへ渡す。回答を得るためのプロンプト再送や仲介LLMは使わない。途中経過は端末にそのまま表示し、読み上げるのはStopフックの確定本文だけ。

端末内のSpaceは文字入力。音声は端末上の「音声入力」、既存の音声ボタン、F13〜F24のPTTキーから利用する。端末外では既存のSpace操作を維持する。入力途中・応答待ちの端末へ音声を混ぜない。書きかけから音声に戻る場合は「入力取消」（Ctrl+U）を押す。これは実行中のClaudeをキャンセルする操作ではない。

実ClaudeとChromiumの結合試験では、通常/SP/Gridの表示・端末入力・確定回答のWAV化・リサイズ・再接続、および模擬マイクを用いたブラウザ録音からSTT経路への接続を確認した。STTとTTSの外部サービスはこの自動試験ではスタブに置き換える。実マイクの認識精度とスピーカーでの聴取は別途実機で確認する。

適用後の自動確認では、試験スロットの一覧反映と、認証付き会話APIからの固定試験文の回答・WAVチャンクを確認する。結果は `~/.local/state/argos/claude-tmux-apply-status.json` の `ready` に記録する。これはマイク入力・スピーカーから実際に聞こえることの証跡ではない。

利用者の明示的な会話リセットでは、実行中ターンがないことと所有権を確認して試験セッションだけを終了する。過去のフック記録は世代別ファイルへ退避する。進行中の会話へのリセットは拒否する。

## 手動で会話する

tmuxとログイン済みのClaudeが必要。ARGOSの既存設定は書き換えない。

```sh
cd /opt/argos
uv run python -m argos.tools.claude_tmux_probe
```

`あなた>` に自由な文章を入力する。たとえば、最初に架空の合言葉を伝え、次に「さっきの合言葉は？」と聞く。質問に対して選択メニューではなく、自由な文章で返答できるかも確認する。

- ツール実行とMCPはこの手動試験では無効。ファイル修正・コマンド実行の試験にはならない。
- 回答後に表示される `tmux attach-session -t ...` を別の端末で実行すると、対話型Claudeの画面をそのまま見られる。
- attachした画面からdetachする場合は `Ctrl+b` の後に `d`。試験中は入力元を試験コマンド側だけにし、attachした画面から同時に文章を送らない。
- `/quit` は試験画面だけを終了する。同じコマンドを再実行すると、同じClaudeと会話を続ける。既存CLIセッションからの自動移行はしない。
- 初回の信頼確認やログイン画面で止まる場合は、端末で手動確認する。60秒以内に起動フックを確認できなければ、本文を送らずエラーにする。
- 応答待ちの既定は1800秒。`--timeout-seconds 0` は無期限。タイムアウトやCtrl+CはClaude自体を停止しない。未確定の発言を自動再送しないため、その後は安全側に停止する。
- 新しい試験会話には `--name 別の試験名` を指定する。失敗した試験セッションを自動で削除・再起動しない。
- 永続データは `~/.local/state/argos/tmux-probe` 以下。フックには回答本文が含まれるため、実際の機微な会話は使わない。終了後もファイルとClaudeプロセスは残る。
- 停止する場合は表示された所有セッション名を確認し、その名前だけを `tmux kill-session -t セッション名` で終了する。`tmux kill-server` は他の作業を停止するので使用しない。終了した試験の再開はまだ未対応で、新しい試験名を使う。

## 自動で実Claudeを確認する

```sh
ARGOS_TEST_CLAUDE_LIVE=1 uv run pytest tests/test_claude_tmux_live.py --override-ini addopts='' -v
```

ツールなしの4ターンを実際に生成するため、Claudeの利用枠を消費する。合言葉の保持に加え、質問への選択肢外の自由回答も確認する。テスト終了時はこのテストが作ったセッションだけを停止する。通常のpytestでは、この実Claude試験をスキップする。

## ARGOS結合試験用の設定

以下はバックエンド選択の設定例。運用中の設定には、前述の専用スロットを追加した。通常運用スロットは置き換えない。

```yaml
agent:
  slots:
    - type: local
      name: Claude tmux試験
      provider: claude
      execution_mode: tmux
      cwd: /opt/argos
      tmux_timeout_seconds: 1800
```

既存のスロット一覧に別の1件として追加する。`execution_mode` 未指定は従来どおり `cli`。`tmux`はClaude・claudecode・codex・antigravityに対応する。

既存ClaudeCliClientと同じく、権限モードの既定はbypassPermissions。手動試験コマンドではこれに加えてツールを無効化しているが、上のスロット設定例はツールを無効化していないため、実行権限を理解した環境でのみ使う。共通フック設定は書き換えず、スロット専用のフックファイルを起動時に渡す。

RunnerやARGOSは設定を起動時に読むため、設定を追加した場合は対象プロセスの再起動が必要。再起動を行う際は実行中ジョブへの影響を確認する。既存のリモートARGOSスロット自体の設定は変えず、接続先ARGOSも更新したうえで、接続先の対象ローカルスロットでtmuxを選択する。旧版の接続先は従来表示を維持する。

現時点ではStopの確定本文のみ音声化する。未確定ターンの自動復旧・終了したCLIの自動再起動は行わない。端末で入力した文章は会話履歴では「端末から入力」と記録し、実際の内容は端末側に残る。ブラウザを閉じてもCLIは終了しないが、OS再起動後のCLI復元やsystemdのtmuxライフサイクル統合は対象外。搬送API・制限・ライセンスは[端末表示の仕様](tmux-console.md)を参照。

ブラウザ結合試験を再実行する場合:

```sh
ARGOS_TEST_CONSOLE_BROWSER=1 uv run --with playwright pytest tests/test_console_browser.py --override-ini addopts='' -v
```

ログイン済みClaude、`/snap/bin/chromium`、ブラウザ音声のデコード用ffmpegが必要。試験専用のセッションだけを作成・終了し、実運用スロットは操作しない。
